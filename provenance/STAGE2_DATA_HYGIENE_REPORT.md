## 2. Confirmation — what entered `stage2_work/`

**No prohibited material was copied into `stage2_work/`.** The working
area contains only the Stage 2 deliverables: the four reports, the
clean conversion implementation, the equivalence test and its captured
output, the sanitised `clip_sides` derivative, the two sanitised shell
drivers and the sanitised Step 3 log copy.

The single data-derived file is `stage2_work/clip_sides_sanitised.csv`.
It was verified in Area C to contain **no restricted data**: its
columns are clip keys (file names), vessel class labels, recording
dates, durations, an ambient flag and the Step 3 side assignments —
metadata about the VTUAD clip inventory. It contains no audio, no
South African competition data, no competition test data, and no MMSI
values (the MMSI column was removed; verification in
`STAGE2_IDENTIFIER_AUDIT.md` §3). The sanitised drivers and log copy
contain code text and log text only, with machine paths replaced.

No dataset was downloaded, extracted or regenerated at any point in
Stage 2, and no file outside `stage2_work/` was created or modified.

## 3. Remaining uncertainties

- Sizes are filesystem measurements (`du`) taken on 18 November 2026;
  they are approximate at the level of filesystem block allocation and
  are given for release-planning scale, not as exact byte counts

  the filesystem where quoted to three figures).
- The inventory covers the working tree as it stands. The frozen
  `archive/` was not inventoried for this report: it is the evidence
  vault, is never a release source, and its contents are fixed by
