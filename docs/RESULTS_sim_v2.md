# Simulator v2 + second model — results (2026-11-16)

Status: **candidate only. NOT submitted to Zindi.** Godson decided: hold v1,
improve the simulator first, then submit the improved version. This file is
the pre-submission record for that submission.

## What changed in the simulator (v1 → v2) and why

All changes target weaknesses named in `RESULTS_sim_v1.md`. Code:
`code/simulate_v2.py`, `code/train_sim_v2.py`. Fixed seed 20261116
throughout; share prior, missingness pattern, ambient-addition probability
(0.30) and split discipline are **unchanged** (the split code and RNG call
order are identical to v1, so background-window and passage-clip pool
memberships are exactly v1's — verified: pool sizes 65,838 / 5,724 / 3,459 /
12,632 match v1).

1. **Longer passage events.** v1 placed one short clip segment (pool median
   3 min) once per window. v2 assembles events to a target duration —
   mixture 45% U(12,15), 25% U(8,12), 20% U(4,8), 10% U(1,4) minutes —
   using the longest clips whole and concatenating clips end to end with a
   1-minute boundary blend (the finest fade that exists at minute
   resolution), each piece carrying its own ±3 dB relative gain jitter.
   Realised event durations (train): mean 10.0 min, median 11, **47.9% ≥
   12 min**, 7.9% exactly 15 (full window). v1's realised mean was ≈3–4 min.
2. **Wider variation.** Time-warp ×0.5–2.0 (v1: ×0.7–1.4); per-band channel
   colouring ±7 dB (v1: ±4 dB); new smooth per-minute gain envelope
   (±3.5 dB) over each event.
3. **Ambient segments.** The 16 ambient clips (30–37 min each) are sliced
   after the clip-level split into non-overlapping 4–8 min segments:
   **72 train / 17 val blocks** (v1 used 13/3 whole clips). Ambient
   additions are assembled from segments exactly like vessel events.
4. **Level-stratified backgrounds.** Background windows are sampled
   uniformly across total-level deciles of their pool, so quiet
   backgrounds (which raise relative shares — a named v1 caveat) are well
   represented instead of being swamped by mid-level Richards Bay windows.
5. **Training fix.** LightGBM round cap 1500 → 6000, early-stopping
   patience 100 → 200 on the same internal 90/10 split. **Early stopping
   fired: best iteration 5547** (v1's best was the 1500 cap itself, i.e.
   v1 never stopped). All other hyperparameters and the 549-feature set
   are identical to v1; B1 statistic still one feature among many.

## Validation — v1 vs v2 on identical protocols

Scores are 1 − RMSE. "v2 sets" were generated by the v2 simulator under the
exact v1 holdout protocol; "v1 sets" are the original v1 files. B0 =
constant 0.1 on identical sets. Both models are scored on both generations.

**On the v2 sets:**

| set | B0 | v1 model | v2 model |
|---|---|---|---|
| val_random | 0.7548 | 0.9008 | **0.9110** |
| val_site (Bird Island + Fish Hoek unseen) | 0.7550 | 0.9005 | **0.9082** |
| val_period | 0.7507 | 0.8969 | **0.9094** |
| val_long (new; forced long events only) | 0.7211 | 0.8685 | **0.8981** |

**On the v1 sets:**

| set | B0 | v1 model | v2 model |
|---|---|---|---|
| val_random | 0.7609 | **0.9169** | 0.9094 |
| val_site | 0.7529 | **0.9049** | 0.8978 |
| val_period | 0.7528 | **0.9115** | 0.9033 |

Reading: the v2 model beats the v1 model on **every** v2 set (+0.008 to
+0.013 on the standard sets, **+0.030 on val_long**) — the v1 model,
trained on short events, is measurably weak exactly where v1's simulator
was unrealistic. On v1's own short-event sets the v2 model gives back
0.007–0.008 to the v1 model: it is less specialised to that world, by
design. Null behaviour stays healthy in both models (mean prediction on
true-zero windows 0.015–0.051 across sets, vs B1's 0.398).

Pressure map, v2 model (RMSE): by true share band (val_random) 0 → 0.048,
0–0.1 → 0.073, 0.1–0.3 → 0.089, 0.3–0.6 → 0.110, 0.6–1.0 → 0.168; by
missingness (val_random) 0 missing minutes 0.074, 1 → 0.102, ≥2 → 0.118.
Same shape as v1: error grows with share and with missing minutes.
val_site by site: Bird Island 0.089, Fish Hoek 0.116 (weakest, as in v1,
but improved from v1's 0.146 on its own set). val_long share bands rise to
0.185 in the 0.6–1.0 band — long, loud events remain the hardest case.
Full tables: `models/sim_v2_validation.json`. Top features (gain) are the
same acoustic story as v1: low-band energy fraction, per-band temporal std
(~251 Hz, ~7.9 kHz), band energy shares (~794 Hz, ~251 Hz, ~7.9 kHz).

## Test predictions — the warning stands

`submissions/submission_sim_v2.csv` (sha256 3e9eab8cb284a812…) **passes**
`code/validate_submission.py` (1,500 rows, IDs exact, values finite in
[0,1]). Predicted share on Test.csv: **mean 0.330, median 0.285, 12.6%
below 0.05** — essentially identical to v1 (mean 0.330, median 0.286,
14.3% below 0.05; the two prediction vectors correlate 0.958, mean absolute
difference 0.050).

That is the honest headline of this phase: **fixing event length and
widening variation improved the model inside the simulator's world but did
not move its reading of the real test windows toward the synthetic prior.**
So the simulator–test gap is probably *not* mainly about passage duration.
A cross-check strengthens this: a constant-0.1 predictor under our share
prior would score RMSE 0.2466, almost exactly the organisers' benchmark
0.2461 — so the prior's overall scale is consistent with the benchmark,
and the inflation sits in what the model reads as "added-like" energy in
real windows, not in a mis-set prior. Remaining candidate causes,
unresolved: (a) the organisers' VTUAD→band conversion differs from the
notebook's reference `minute_band_power` (the notebook itself calls its
conversion unverified); (b) their withheld test backgrounds differ in
character from the released periods (e.g. more real vessel traffic, which
both models read as additions); (c) a different VTUAD subset or
per-minute (rather than per-window) share definition. None of these can be
distinguished from synthetic data alone — **the planned smoke-test
submission of this file is the measurement that resolves it**, and its
public score should be read as a simulator diagnostic, not as a final
result (public is ~30% of test; the private 70% decides prizes).

## Failures, shortcuts, caveats (stated plainly)

- One evaluation run crashed on a LightGBM API misuse (`lgb.Booster`
  needs `model_file=` as a keyword in 4.7) *after* training had completed
  and the model was saved; the script now resumes from the saved model
  (best iteration 5547 recorded in `models/lgbm_sim_v2_best_iter.txt`) and
  the evaluation was rerun cleanly. No numbers were affected.
- The v2 model file is 34.5 MB (5,547 trees) vs v1's 9.2 MB — larger than
  ideal for the code-review package; if this becomes the frozen model,
  consider a distilled/retained-rounds variant later. Not changed now:
  altering it would invalidate the comparison above.
- val_long backgrounds come from the val_random pool (same windows,
  different mixes and only long events) — it is a duration stress test,
  not an independent background holdout.
- Fish Hoek still rests on few background windows (296 in the pool); its
  holdout numbers carry wide uncertainty in both versions.
- Two sites (Cape Recife, Riy Banks) still contribute no background
  windows; nothing in v2 changes that.
- The test-prediction distribution did not improve (see warning). v2 is
  submitted next because it is the more robust model under every
  synthetic stress we can build — not because the domain gap is closed.
- Versions (venv, for the code review): python 3.12.3, numpy 2.5.5,
  pandas 3.1.1, pyarrow 26.0.1, scipy 1.18.1, lightgbm 4.7.0,
  scikit-learn 1.9.1, soundfile 0.14.0. Seed 20261116 everywhere.
  Nothing was submitted or posted anywhere.
